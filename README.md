# MoexData

Десктопное приложение и консольная утилита для выгрузки исторических данных MOEX Algopack: свечи, TradeStats, OrderStats, OBStats, HI2, MegaAlerts, FUTOI, а также дивиденды и сплиты. Рынки: акции, фьючерсы, валюта, индексы, облигации, опционы. Результат сохраняется в CSV или Parquet, один файл на пару «тикер — набор данных».

Работает поверх библиотеки moexalgo. Нужен ключ Algopack.

## Установка

Python 3.12 или новее.

```
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Запуск

```
venv\Scripts\python.exe run.py
```

При первом запуске введите ключ Algopack в поле вверху окна и нажмите «Сохранить». Ключ хранится в `%APPDATA%\MoexData\settings.json`, там же сохраняются остальные настройки. Кнопка «Проверить ключ» делает тестовый запрос. Вместо поля можно задать переменную окружения `MOEXALGO_APIKEY` или `ALGOPACK_APIKEY`.

## Интерфейс

Вкладки:

- Импорт данных. Рынок, тикеры (список загружается с биржи, есть поиск), период, интервал свечей, наборы данных, папка и формат. Под настройками периода показывается, на сколько запросов разобьётся выгрузка.

Выбор тикеров: щелчок выбирает один инструмент и сбрасывает прежний выбор, в том числе скрытый поиском. Ctrl или Shift со щелчком добавляют инструменты к выбору, «Добавить все найденные» добавляет всё, что показывает поиск. Точный состав выгрузки виден в блоке «К выгрузке» под списком, лишнее убирается кнопкой «Убрать» или двойным щелчком. При запуске выбранные тикеры перечисляются в журнале.
- Дополнительно. Постобработка, проверка качества, догрузка, корректировки цен, склейка фьючерсов, сеть, параметры CSV и Parquet.
- Журнал. Ход выгрузки, предупреждения, итог. Журнал можно сохранить в файл.
- Ошибки. Таблица по каждой паре «тикер — набор» со статусом, диапазоном, кодом и сообщением. Кнопка «Повторить неудачные» перезапускает только проблемные пары.
- Справка.

Быстрый выбор периода: 7, 30, 90 дней, год, 3 года, с начала года. Галочка «Вся доступная история» отменяет даты, см. ниже.

## Наборы данных

- candles: свечи OHLCV. Интервалы 1, 5, 10, 15, 20, 30 минут, 1, 2, 3, 6, 12 часов, 1, 5, 10 дней, 1, 2, 4 недели, 1 месяц. Все рынки.
- tradestats: метрики сделок по 5-минутным интервалам. Акции, фьючерсы, валюта.
- orderstats: метрики заявок. Акции, фьючерсы, валюта.
- obstats: метрики стакана. Акции, фьючерсы, валюта.
- hi2: индекс концентрации. Акции, фьючерсы, валюта.
- alerts: MegaAlerts, сигналы аномальной активности. Акции, фьючерсы, валюта.
- futoi: открытые позиции физических и юридических лиц. Фьючерсы.
- dividends: дивиденды. Акции.
- splits: сплиты и консолидации. Акции.

## Разбиение на запросы

ISS отдаёт не больше 10 000 строк за запрос, поэтому длинный период качается частями и склеивается:

- минутные свечи: 1 день на запрос;
- 5-30 минут: от 5 до 30 дней;
- 1 час: 60 дней, 2-12 часов: 120-180 дней;
- дневные свечи: 5 лет;
- 5D, 10D, недели и месяц: одним запросом;
- TradeStats, OrderStats, OBStats, FUTOI: 30 дней;
- HI2, MegaAlerts: 90 дней;
- дивиденды и сплиты: одним запросом.

Размер части можно задать вручную. Если ответ упёрся в лимит, в журнал пишется предупреждение с советом уменьшить часть.

После склейки удаляются дубли на стыках частей, строки сортируются по времени, добавляется колонка с тикером. Колонки begin, end, tradedate и systime сохраняются как дата и время, пустые строки из ответов ISS превращаются в пропуски. Всё это отключается на вкладке «Дополнительно».

## Выходные и биржевое время

С 2025 года MOEX торгует и по выходным, поэтому субботы и воскресенья по умолчанию тоже выгружаются. Галочка «Пропускать выходные дни» или `--skip-weekends` убирает их из всех наборов, включая строки внутри многодневных частей.

Даты считаются по московскому времени, а не по часам компьютера. День, торги или расчёт метрик за который ещё не закончились (до 03:00 МСК следующих суток), в кеш не попадает: при следующей выгрузке он скачается заново, а в отчёт пишется предупреждение о неполных данных.

## Торговый календарь

Перед выгрузкой приложение берёт календарь рынка из ISS (`/iss/calendars`). Он нужен для двух вещей:

- не отправлять запросы за праздники и выходные без торговой сессии;
- после склейки найти торговые дни, за которые данных нет. Такие дни попадают в журнал, отчёт и вкладку «Ошибки». Проверяется отрезок между первым и последним днём с данными. Выходные до первой выходной сессии конкретной бумаги пропуском не считаются. MegaAlerts не проверяются, сигналы бывают не каждый день.

Календарь сохраняется в папку выгрузки файлом `calendar_stock_<начало>_<конец>`, сводка (торговые дни, выходные сессии, праздники в будни) пишется в отчёт. Запрашивается не глубже 10 лет. Если календарь недоступен, выгрузка идёт без него. Отключается галочкой или `--no-calendar`.

## Вся доступная история

Вместо дат приложение двумя запросами узнаёт у биржи, с какой даты и по какую у инструмента есть данные, отдельно для каждой пары «тикер — набор». Для свечей глубина определяется по тому интервалу ISS, из которого строится выбранный период: история минуток короче дневной. Если данных нет, пара помечается как пустая. Если узнать глубину не удалось, берётся период из полей дат.

Вся история минутных свечей - это тысячи запросов, поэтому приложение переспрашивает перед стартом. Прерванную выгрузку можно продолжить, скачанное лежит в кеше.

## Кеш частей

Каждая скачанная часть сохраняется в `<папка выгрузки>/.moexdata_cache`. При повторном запуске с теми же параметрами уже скачанные части не запрашиваются, пустые дни тоже запоминаются. Кеш очищается кнопкой на вкладке «Дополнительно».

## Догрузка до сегодняшнего дня

Галочка «Догружать ранее выгруженные файлы» или `--update`. Для каждой пары ищется прежний файл по шаблону имени, из него берётся последняя дата, и качается только хвост: от последнего дня в файле до сегодня. Последний день перекачивается, потому что мог быть сохранён неполным. Старые и новые строки склеиваются, файл получает новое имя с новой датой конца, прежний удаляется. Пары без прежнего файла выгружаются как обычно. С режимом «один файл на все тикеры» догрузка не работает.

## Проверка качества

После склейки каждый набор проверяется автоматически, данные при этом не меняются:

- ohlc: максимум ниже открытия или закрытия, минимум выше них;
- nonpositive_price: нулевые и отрицательные цены;
- negative_volume: отрицательные объёмы и обороты;
- duplicate_time: повторяющиеся метки времени;
- unsorted: строки не по порядку;
- price_jump: скачок больше 5% между соседними строками, так выглядят и дивидендные гэпы;
- vwap_range: у акций оборот, делённый на объём, вне диапазона бара;
- cross_check: 5-минутные бары, собранные из минутных свечей, сравниваются с TradeStats по максимуму, минимуму и объёму, совпадение ниже 95% даёт предупреждение;
- nulls: пропуски по колонкам, справочно.

Результаты пишутся в журнал, в колонку «Сообщение» и в раздел quality JSON-отчёта. Отключается галочкой или `--no-validate`.

## Дивиденды, сплиты и скорректированные цены

Сплиты берутся из ISS (`statistics/engines/stock/splits`), это бесплатно.

С дивидендами сложнее. Бесплатный раздел ISS `securities/<тикер>/dividends` сейчас возвращает карточку бумаги без выплат, а раздел корпоративных действий `cci/corp-actions/dividends` требует отдельной подписки MOEX, с ключом Algopack он отвечает 403. Поэтому дивиденды берутся из своего файла `dividends.csv` в папке выгрузки:

```
secid;registryclosedate;value;currencyid
SBER;2025-07-18;34.84;RUB
SBER;2024-07-11;33.30;RUB
```

Разделитель - запятая или точка с запятой, currencyid можно не указывать. Если файла нет и подписки CCI тоже нет, набор dividends завершается ошибкой unsupported с подсказкой.

К каждому дивиденду добавляется last_buy_date, последний день покупки под выплату: за один рабочий день до закрытия реестра (T+1, с 31.07.2023), раньше за два.

Галочка «Цены с поправкой на дивиденды и сплиты» или `--adjust` добавляет к свечам акций колонки adj_open, adj_high, adj_low, adj_close и adj_factor. Корректировка назад: последние цены совпадают с биржевыми, история до гэпа умножается на (1 - дивиденд / закрытие накануне), до сплита - на отношение «до / после». Дата гэпа - первая сессия после дня покупки, это может быть и субботняя сессия. Валютные дивиденды не учитываются. Если дивиденды недоступны, поправка делается только на сплиты, в отчёт пишется предупреждение.

## Склейка фьючерсов

На рынке фьючерсов галочка «Склеивать контракты актива» или `--continuous` превращает тикер в непрерывный ряд. Тикер - код актива (Si) или любой его контракт (SiZ5). Серия контрактов вместе с истёкшими берётся из `statistics/engines/futures/markets/forts/series`.

- Каждый контракт держится до N рабочих дней до экспирации, по умолчанию 5 (`--roll-days`), со следующего дня ряд переходит на следующий контракт.
- «Только квартальные контракты» (`--quarterly`) пропускает месячные. У активов без квартальных контрактов берутся все.
- Колонка contract показывает, из какого контракта строка. Файл называется `Si_cont_...`.
- Гэпы на стыках (`--roll-adjust`) считаются по дневным закрытиям обоих контрактов в последний общий день. diff сдвигает историю на разницу цен (колонки adj_* и adj_shift), ratio умножает на отношение (adj_factor), none ничего не меняет. Корректировка делается для свечей, остальные наборы склеиваются с колонкой contract.

## Файлы на выходе

По умолчанию файлы кладутся в подпапку тикера и называются `{ticker}_{dataset}{period}_{start}_{end}`, например `SBER_candles_1min_2025-09-08_2026-09-08.parquet`. Шаблон имени меняется на вкладке «Дополнительно», доступны {ticker}, {dataset}, {period}, {start}, {end}, {market}.

Также можно включить:

- один общий файл на все тикеры вместо файла на тикер;
- сохранение исходных частей в подпапку parts;
- JSON-отчёт `moexdata_report_<время>.json`: параметры, итоги, предупреждения, проверка качества, сводка календаря, результат по каждой паре;
- CSV: разделитель, десятичный знак, кодировка, сжатие в .csv.gz;
- Parquet: сжатие snappy, gzip, brotli, zstd или без сжатия.

## Сеть и ошибки

Временные сбои (5xx, обрывы связи, 429) повторяются автоматически, число повторов и паузы настраиваются. Ошибка одного дня или тикера не останавливает выгрузку, при отказе по ключу выгрузка прерывается.

Коды ошибок:

- no_api_key: ключ не задан;
- auth, forbidden: 401 или 403, ключ не принят или нет подписки;
- rate_limit: 429, увеличьте паузу между запросами;
- server: 5xx на стороне MOEX;
- network, timeout: нет связи с биржей, проверьте интернет и прокси;
- not_found, unknown_ticker: инструмента нет на выбранном рынке;
- unsupported: набор недоступен на рынке или источник данных недоступен;
- bad_params: некорректные даты или период;
- bad_response: биржа вернула некорректный ответ;
- disk: не удалось записать файл.

## Консольный режим

Всё, что есть в окне, доступно из командной строки. Значения, не указанные явно, берутся из сохранённых настроек.

```
venv\Scripts\python.exe -m moexdata.cli --check-key
venv\Scripts\python.exe -m moexdata.cli --list-tickers --market futures
venv\Scripts\python.exe -m moexdata.cli --tickers SBER,GAZP --start 2025-01-01 --end 2025-12-31 --datasets candles,tradestats --period 1min --format parquet --out data
venv\Scripts\python.exe -m moexdata.cli --tickers SBER --full-history --datasets candles --period 1D
venv\Scripts\python.exe -m moexdata.cli --tickers SBER --datasets candles,tradestats --update
venv\Scripts\python.exe -m moexdata.cli --tickers SBER --datasets candles,splits --period 1D --start 2015-01-01 --end 2026-09-08 --adjust
venv\Scripts\python.exe -m moexdata.cli --market futures --tickers Si --continuous --roll-days 5 --roll-adjust diff --quarterly --datasets candles --period 1h --start 2024-01-01 --end 2026-09-08
```

Параметры:

- `--api-key`: ключ, если не брать его из настроек;
- `--market`: shares, futures, currency, index, bonds, options;
- `--tickers`: тикеры через запятую;
- `--datasets`: candles, tradestats, orderstats, obstats, hi2, alerts, futoi, dividends, splits;
- `--start`, `--end`: даты в формате ГГГГ-ММ-ДД;
- `--full-history`: вся доступная история;
- `--period`: интервал свечей;
- `--format`: csv или parquet;
- `--out`: папка выгрузки;
- `--chunk-days`: размер части вручную;
- `--no-cache`: не использовать кеш;
- `--skip-weekends`, `--with-weekends`: пропускать или качать выходные;
- `--no-calendar`: не использовать торговый календарь;
- `--combine`: один файл на все тикеры;
- `--no-validate`: без проверки качества;
- `--update`: догрузка;
- `--adjust`: цены с поправкой на дивиденды и сплиты;
- `--continuous`, `--roll-days`, `--roll-adjust`, `--quarterly`: склейка фьючерсов;
- `--verbose`: печатать каждый запрос;
- `--list-tickers`: список инструментов рынка;
- `--check-key`: проверка ключа.

Код возврата: 0 - успех, 1 - были ошибки по части пар, 2 - выгрузка не запустилась.

## Диагностика

Если календарь, дивиденды, сплиты или серии фьючерсов приходят пустыми:

```
venv\Scripts\python.exe -m moexdata.diag SBER Si
```

Команда запрашивает эти справочники через шлюз Algopack и через публичный iss.moex.com и сохраняет ответы в `data/iss_diag.json`. Сама выгрузка пробует оба адреса автоматически.

```
run.py                 запуск окна
moexdata/
  settings.py          настройки и ключ
  timeutil.py          московское время
  errors.py            классификация ошибок
  cli.py               консольный режим
  diag.py              диагностика справочников ISS
  api/
    client.py          работа с moexalgo: тикеры, части данных, глубина истории, серии фьючерсов
    datasets.py        рынки, интервалы, наборы данных, правила разбиения
    calendar.py        торговый календарь
    corporate.py       дивиденды и сплиты
    iss.py             справочные запросы к ISS
  core/
    exporter.py        выгрузка: план, кеш, повторы, склейка, догрузка, отчёт
    chunking.py        разбиение периода на запросы
    quality.py         проверка качества
    adjust.py          поправка на дивиденды, сплиты и швы контрактов
    continuous.py      расписание склейки фьючерсов
    writer.py          запись CSV и Parquet
  gui/
    app.py             окно приложения
tests/
```
